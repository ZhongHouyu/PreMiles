# 一页纸速览 · 基于跟车报文数据的整车能耗分析 AI 方案

**创科升「AI 应用方案大赛」** ｜ 赛道：AI 辅助**数据分析 / 数据整理** ｜ 形式：**已落地方案**（PPT + 现场演示）
报名截止 **9/30** ｜ 路演 **10/13** ｜ 团队 **≤3 人** ｜ 奖金 500~20,000 元（按"工作效率提升价值"发放）

---

## ① 问题：数据量极大，信息量极小

| 一边 | 另一边 |
|---|---|
| 整车 CAN / J1939 报文，**10~100 Hz**，**一台车一天 GB 级** | 车队长只会问：**"这车为什么费油？"** |
| `0x0CF00400`、`SPN 183`、`SPN 190`……满屏十六进制 | **只知道百公里 32 L，不知道高在哪** |

| 五个真实痛点 | 一句话 |
|---|---|
| P1 隔着"翻译" | 报文语言 ↔ 业务语言，今天靠人肉 |
| P2 归因不了 | 多少耗在怠速、多少顶风、多少是习惯？说不清 |
| P3 对比不公平 | 山区重载 vs 城配空载直接比，结论必错，司机不服 |
| P4 异常靠人盯 | 等故障码亮起才发现，**能耗损失已发生几个月** |
| P5 人力不可扩展 | 单台车单日 **4 小时以上**，车队一大就废 |

## ② 方案：一条流水线，从 T-Box 到一份司机看得懂的报告

| 层 | 做什么 |
|---|---|
| 采集接入 | T-Box / CAN 记录仪 → MQTT/Kafka，断点续传 + 去重。**不依赖新硬件** |
| 存储 | 原始报文（Parquet/Blf）+ 时序库 TDengine + 分析库 ClickHouse/DuckDB |
| 解析治理 | DBC/J1939 解码 → 对齐 UTC 1 Hz → 清洗 → **质量评分 0~100** → 单位归一 → 缺信号补全 |
| 物理 + AI | 能量守恒模型 → 工况切分 → 特征工程 → **基线预测(GBDT)** → **残差异常(IsolationForest)** → 驾驶评分 → **车况衰减(CUSUM)** |
| 应用 | 能耗看板 / 单车体检报告 / 异常预警 / 节油排行 / **LLM 中文诊断报告** / 调度建议 |

**核心逻辑：先物理，后 AI。** AI 只学物理模型解释不掉的**残差** → 样本需求低、结果可解释。

---

## ③ 技术内核：一张能量瀑布 + 一个残差

**能量瀑布（一个数字 → 九个可归因分项）**

`E_chem = E_idle 怠速 + E_aux 附件 + E_roll 滚阻 + E_aero 风阻 + E_grade 坡道 + E_kinetic 净加速 + E_brake 制动耗散 + E_dt_loss 传动损失 + ε 残差`

| 要点 | 数字 |
|---|---|
| 柴油换算 | LHV 42.8 MJ/kg、密度 0.84 kg/L → **9.99 kWh/L** |
| 电车能量 | `P_batt = U·I`，`E_batt = ∫P_batt dt`；冬季**附件（空调/加热）占 20%~35%**，必须单拆 |
| 残差硬约束 | 各分项之和必须回到总量，**ε < 5%** |
| 三个难点 | 质量未知→轴荷/RLS 辨识；坡度未知→GNSS 海拔+卡尔曼融合；无风速→按 0 处理并反标 `C_d·A` |

**AI 残差：** `r = 实际 − 预测` ｜ r≈0 正常 ｜ r>0 比同类更耗能→归因 ｜ r<0 优秀→作标杆
**公平比较器：** 输入线路地形、载重、车型车龄、温度、时段 → **山区重载不与城配空载比**（司机愿意接受的前提）

## ④ 三个硬指标（**原型已实测，可现场复现**）

| # | 指标 | 目标 | **实测** | 怎么验 |
|---|---|---|---|---|
| 1 | **对账误差**（能耗 vs 加油小票/充电订单） | **< 5%** | **1.08% ~ 3.57%** | **两条油耗路径对账**（燃油率积分 / 累计油耗差分）+ **三方里程校验**（车速积分 / 里程表 / GNSS） |
| 2 | **效率提升** | **4 h → < 3 min**，**> 80×** | **单车能耗分析 0.04 s**；车队周报 3 人天/周 → 0（**约 150 人天/年**） | 人工基线 vs 自动化计时 |
| 3 | **年化收益**（100 台车） | **54 万 ~ 144 万元** | — | 8 万 km × 30 L/100km × 7.5 元/L = **18 万/车/年**；节能 3%/5%/8% → 单车 5,400/9,000/14,400 元 |

**AI 层实测：** 样本外 **R² = 0.894**、**MAPE = 4.61%** ｜ 异常检测 **查准率 100% / 查全率 79.2% / F1 0.884**（56 个正常车次**零误报**）

**三道自检，全过才发报告：** 能量守恒 **~1e-14%（浮点零）** ｜ 三方里程互差 **0.01%~0.21%** ｜ 加油对账 **1.08%~3.57%**

**其他 KPI：** 解码成功率 **实测 100.0000%**（235,711 帧）｜ 单车分析 **0.04 s** ｜ 节油潜力测算偏差 <30% ｜ 单车百公里能耗下降 **3%~8%**

**新能源车队（100 台）：** 8 万 km × 1.2 kWh/km × 0.8 元/kWh = **76,800 元/车/年**；节能 5% → 车队 **38.4 万元**（另加电池寿命、续航预估、充电策略收益）

> **口径声明：** 3%~8% 参考行业公开的车队能耗管理与驾驶行为改善经验区间，实际收益需以本车队基线标定。**路演对外只用保守值 3%（54 万起）。**
> **仿真边界：** 上述精度与检出指标在**带真值的仿真数据**上实测通过，证明算法自洽且算得准；**不能替代真车验证**，拿到真车数据后必须重新实测。

## ⑤ 落地时间表：13 天倒排（9/30 报名 → 10/13 路演）

| 阶段 | 时间 | 关键动作 | 交付 |
|---|---|---|---|
| 0 数据摸底 | **D1–D2（2 天）** | ≥3 台车 ≥5 天报文（.blf/.asc/candump）+ DBC + **同期加油小票/充电订单** | 数据可用性结论 + 信号清单 + 质量评分报告 |
| 1 MVP | **D3–D7（5 天）** | 解码/清洗/重采样、里程三路径校验、能耗主算法 + 对账**打进 5%**、瀑布图 | **一台真车的能耗体检报告（路演核心素材）** |
| 2 智能化 | **D6–D10（部分并行）** | 工况切分、特征工程 + 基线预测、异常检测 + 司机评分 + SHAP | 异常事件清单、司机排名、归因解释 |
| 3 报告与彩排 | **D9–D13** | LLM 报告 + 数值校验、看板/静态报告、**演示彩排（离线可跑）** | 路演 PPT + 可现场运行的 Demo |
| 4 规模化 | 获奖/立项后 | 全车队接入、Spark 化、与加油/充电/运单打通、A/B 验证 | 常态化能耗管理体系 |

**最大风险 = 拿不到真实报文** → ① 提前走数据申请流程 ② 仿真数据（**带真值**）先跑通全链路，拿到真车数据**只换数据源，模型与流水线不变** ③ 脱敏单台车做 PoC
**第二风险 = 对账打不进 5%** → 两条油耗路径交叉（燃油率积分 vs 累计油耗差分）+ 三方里程校验 + 自动定位问题信号 + 长窗口对账
