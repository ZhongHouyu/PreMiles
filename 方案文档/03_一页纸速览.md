# 一页纸速览 · 面向整车开发与 VCU 标定的整车能耗归因与降耗方向 AI 方案

**创科升「AI 应用方案大赛」** ｜ 赛道：AI 辅助**数据分析 / 数据整理** ｜ 形式：**已落地方案**（PPT + 现场演示）
**受众**：**整车开发商**（整车能耗开发 / 能量管理 / 热管理 / 法规合规 / 竞品对标）· **VCU 开发厂家**（控制策略开发、能量管理标定、HIL 与实车验证）
报名截止 **9/30** ｜ 路演 **10/13** ｜ 团队 **≤3 人** ｜ 奖金 500~20,000 元（按"工作效率提升价值"发放）

## ① 问题：账目有了，**方向**没有

| 一边：数据与账目都在 | 另一边：决策要的答案不在 |
|---|---|
| 整车 CAN / J1939，**10~100 Hz**，一台车一天 GB 级 | 决策者只问：**"这块能耗高，是改设计还是改策略？"** |
| 能算出 32.16 L/100km（且实测对账误差 **1.10%**） | **拆不出**怠速/附件/滚阻/风阻/传动各占多少 |
| `0x0CF00400`、`SPN 183`、`PGN 65257`……满屏十六进制 | 设计参数与 VCU 策略量的语言，靠资深工程师人肉翻译 |

| 六个真实痛点 | 一句话 |
|---|---|
| P1 账目在，归因不在 | 1.25 kWh/km 里**哪一项该动**？说不清 |
| P2 隔着"翻译" | 报文语言 ↔ 设计参数 / 标定阈值，今天靠人肉 |
| P3 对比不公平 | 山区重载 vs 城配空载混着比，**A/B 结论不可信** |
| P4 参数漂移不可见 | 设计值 vs 在用车实际（滚阻、C_d·A、内阻）**无持续反标** |
| P5 闭环缺失 | 策略改动收益靠"跑一圈看看"，缺**同工况回归基线** |
| P6 人力不可扩展 | 一次完整能耗分析 **4 h/车次**，标定项目几百车次 |

## ② 方案：**六步法**，把"能耗高"变成可排期的改进清单

![六步法：拆—比—反—敏—指—验](figures/fig01_six_steps.png)

| 步 | 做什么 | 交付物 | 面向谁的决策 |
|---|---|---|---|
| **拆** | 能量瀑布：总能耗 → 怠速/附件/滚阻/风阻/坡道/动能/制动/传动损失 | 分项占比图 | 全体：先知道花在哪 |
| **比** | 公平基线残差：剥离工况、载荷、地形、温度 | **𝑟 = 实际 − 预测** | 把不可控因素摘出去 |
| **反** | 参数反标定：等效滚阻、`C_d·A`、传动效率、附件功率、电池内阻 | 参数偏差表 | 找"设计与实际不一致" |
| **敏** | 灵敏度与优先级：**Δ分项 / Δ参数 × 可改范围 ÷ 代价** | 排序表 | 决定先改谁 |
| **指** | 降耗方向清单：**设计参数 / VCU 策略 / 标定阈值** + 收益 + 置信度 + 验证方式 | 《降耗方向说明书》 | OEM 改设计、VCU 改策略 |
| **验** | 工况回放 → 台架 / 转鼓 / HIL / 实车 A/B | 回归基线 | 证明真的省下来了 |

**一句话**：把**看不懂的报文**变成**对得上的账本**，再变成**排得出优先级的降耗方向**。

## ③ 技术内核：一张瀑布 + 一个残差 + 一张映射表

**能量瀑布（燃油侧，与原型实现一致）**

𝐸_chem = 怠速与附件 + 传动损失 + 发动机热效率/部分负荷损失(配平项) + [滚阻 + 风阻 + 坡道 + 动能 + 制动需求]

**纯电侧**：𝐸_batt = 驱动 + 附件与热管理 + 电驱与传动损失 − 能量回收

| 要点 | 数字 / 口径 |
|---|---|
| 柴油换算 | LHV 42.8 MJ/kg、密度 0.84 kg/L → **9.99 kWh/L** |
| 纯电能量 | 𝑃_batt = 𝑈 · 𝐼，𝐸_batt = ∫ 𝑃_batt 𝑑𝑡；冬季附件（空调/加热/热管理）**可占 20%~35%**，必须单拆 |
| 硬约束 | 各分项之和必须回到总量——**但这是"按定义闭合"的恒等式，不是物理验证** |
| 三个难点 | 质量未知→轴荷传感器优先（**辨识算法待实现**）；坡度未知→IMU 滑动平均 + GNSS 回归（**卡尔曼融合待实现**）；无风速→按 0 处理并反标 `C_d·A` |

**公平比较器**：输入线路地形、载重、车型车龄、温度、时段 → **山区重载不与城配空载比**，这是 A/B 结论可信的前提。
**AI 残差**：**r ≈ 0** 正常 ｜ **r > 0** 比同类更耗能 → 进入归因 ｜ **r < 0** 优秀 → 沉淀为内标杆。

**参数扰动敏感性（审计复算 `audit/audit.py` 实验 A ——"方向可排序"的依据）**

| 参数设定 | 牵引能耗 | 相对基准 | 账目自洽性检查 |
|---|---:|---:|---|
| 基准（铭牌参数） | 26.87 kWh | — | 通过 |
| `C_d` × 1.6 | 31.23 kWh | **+16.2%** | 通过 |
| `A` × 1.5 | 30.47 kWh | **+13.4%** | 通过 |
| `C_rr` × 3.0 | 42.06 kWh | **+56.5%** | 通过 |
| 整备质量参数 +8000 kg | 26.87 kWh | 0%（质量取自信号） | 通过 |

> **这张表说明两件事**：① 分项能耗对参数高度敏感 → 灵敏度可以直接给方向**排序**；② **参数错标 57% 时"账目自洽"仍然全绿** → 物理校验只能靠**独立观测量**（滑行试验反标滚阻、称重校核质量、长巡航段/风洞反标风阻面积）。

![参数扰动敏感性](figures/fig03_sensitivity.png)

**VCU 可干预量 × 能耗分项（摘要，全表见 `05`）**

| 分项 | 设计侧可改 | **VCU / 标定侧可改** | 分析侧证据 |
|---|---|---|---|
| 怠速/停车 | 起停硬件、电动化附件 | 怠速停机条件、驻车取力、怠速转速 | 怠速时长占比、每百公里怠速秒数 |
| 附件/热管理 | 热泵 vs PTC、保温、风道 | 压缩机占空比、PTC 分级、风扇/水泵按需、目标温度 | 附件功率占比 vs 温度偏离曲线 |
| 制动/回收 | 制动器规格、回收上限 | 回收强度分级、进入/退出阈值、扭矩分配 | **"可回收未回收"事件清单** |
| 传动损失 | 挡位数、速比、润滑 | 换挡线、锁止离合器、挡位保持 | 巡航挡位/转速分布 |
| 空气阻力 | `C_d`、迎风面积、导流板 | 巡航目标车速、限速、预测性滑行 | 巡航车速分布、`C_d·A` 反标值 |
| 坡道/动能 | 轻量化、旋转惯量 | **预测性能量管理（地形前瞻）** | 坡度序列、下坡回收达成率 |
| 电池/热管理（EV） | 内阻、热管理架构 | SOC 窗口、加热/冷却阈值、低温回收限值 | 温度-内阻-回收受限事件 |
| 电驱工作点（EV） | 电机效率 MAP、拓扑 | 双电机扭矩分配、切换门限 | 工作点热力图 vs 高效区 |

> 若能通过 **XCP/A2L** 读到 VCU 内部量，还能再下一层：**目标回收扭矩 vs 实际、热管理请求 vs 实际、限扭与降功率原因时长** —— 这是"能耗偏差里有多少是策略没执行到位"的直接证据。

## ④ 硬指标（**原型已实测，可现场复现**）

| # | 指标 | 目标 | **实测** | 口径 / 怎么验 |
|---|---|---|---|---|
| 1 | 能耗账目 vs 真值 | — | **0.00% / 0.03% / 0.01%** | 燃油化学能口径 |
| 2 | **外部对账误差**（加油/充电） | **< 5%** | **1.08% ~ 3.57%**（均值 1.92%） | 燃油率积分 vs 累计油耗差分；三方里程校验 |
| 3 | 三方里程互差 | < 2% | **0.01% ~ 0.03%** | 车速积分 / 里程表 / GNSS |
| 4 | **参数扰动敏感性** | — | **+16.2% / +13.4% / +56.5%** | 审计实验 A（同上表） |
| 5 | 单车能耗分析耗时 | < 3 min | **0.00 s** | 端到端 **6.8 s**（含仿真与建模，离线单进程） |
| 6 | 数据质量分 | — | **93.2** | 量程断言 + 卡死检测加权 |
| 7 | 基线模型（样本外） | — | 𝑅² = 0.894，MAE 1.71，MAPE = 4.61% | ⚠️ 仿真车队**工况同质**，相对真实项目偏乐观 |
| 8 | 异常检测 | — | **查准 100% / 查全 79.2% / F1 0.884** | ⚠️ 全量自评；折半交叉验证查全 **70.8%**、查准仍 **100%**；56 个正常车次**零误报** |
| 9 | CAN ID 命中率 | ≥ 99.5% | **100.0000%**（235,711 帧） | ⚠️ **不度量信号完整性**（破坏 5% 帧载荷后仍为 100%，靠质量分兜底） |
| 10 | 编码器与跨版本可复现 | — | **3300/3300 一致；CAN 日志 SHA256 一致** | 与 cantools 官方编码器逐帧比对 |

**诚实边界（三条，必须一起讲）**
① 以上精度均在**带真值的仿真数据**上实测，**不能替代真车与台架验证**；
② 车轮侧**分解**是按铭牌参数算的：滚阻恶化 35% 的车次分解与真值差 **9.08%** —— 这**不是误差，是待检测的信号**；
③ 方案已公开 **13 项**待实现 / 近似实现项（质量辨识、卡尔曼融合、参数反标定、`TreeExplainer`、EV 回收效率 MAP 等），见 `01` §4.9。

## ⑤ 落地：13 天到可演示，2 周出第一份方向说明书

| 阶段 | 时间 | 关键动作 | 交付 |
|---|---|---|---|
| 0 数据与接口摸底 | **D1–D2** | ≥3 台车 ≥5 天报文（`.blf`/`.asc`/`.mf4`）+ DBC（**确认有无 CRC**）+ 同期加油/充电记录 + **安排一次滑行试验与一次称重** | 数据可用性 + VCU 可观测性结论 + 质量分报告 |
| 1 MVP | **D3–D7** | 解码/清洗/重采样、里程三路径、能量瀑布、**对账打进 5%** | **一台真车的能耗归因报告（路演核心素材）** |
| 2 智能化 | **D6–D10（部分并行）** | 公平基线、残差判据、**参数反标定 + 灵敏度排序 + VCU 映射表** | 方向清单草案 + 参数偏差表 |
| 3 报告与彩排 | **D9–D13** | 方向说明书生成 + 数值回校验、看板/静态报告、**离线演示彩排** | 路演 PPT + 可现场运行的 Demo |
| 4 立项后 | — | 打通 XCP/A2L、工况回放库、A/B 回归门禁、补齐 §4.9 待实现项 | 能耗回归门禁 |

**2 周 PoC（3 台车）验收四条**：① 对账误差 < 5%；② 完成 1 次滑行试验 + 1 次称重，给出滚阻与质量的反标定区间；③ 输出 ≥5 条降耗方向，**每条含置信度与验证方式**；④ 至少 1 条方向完成台架/HIL 或实车 A/B 复测。

**两个最大风险** → ① **拿不到真实报文/标定数据**：仿真数据（带真值）先跑通全链路，拿到真数据只换数据源；② **参数反标定缺独立观测**：只给带置信区间的估计，并强制附验证建议，绝不把估计当实测。

## ⑦ 一句话收口

> 把**看不懂的报文**变成**对得上的账本**，再变成**排得出优先级的降耗方向**——
> 满屏十六进制，最后变成两句能直接排期的话：
> **「T005-1 总残差 +11.1%：胎压 607 kPa 显著低于标准 822 kPa，滚阻将升高。设计侧查轮胎规格与推荐气压；VCU/标定侧查胎压报警阈值。验证：滑行试验 + 转鼓 + 实车 A/B。」**（车辆侧主导）
